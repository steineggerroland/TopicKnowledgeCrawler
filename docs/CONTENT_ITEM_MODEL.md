# Content Item Model

TopicKnowledgeCrawler historically called every fetched item an `article`.
For n8n compatibility that wrapper name still appears in some workflow fields,
but the payload now carries an explicit `item_kind`.

Current item kinds:

- `article`: RSS/Atom articles and HTML pages.
- `episode`: podcast episodes from `rss+podcast` feeds.

The existing infl0 ingest payload remains compatible: episode fields are
additional fields on the same item object and can be ignored by older infl0
versions.

## Common fields

All item kinds should provide these fields when available:

| Field | Description |
|-------|-------------|
| `id` | Stable item id generated by the crawler. |
| `item_kind` | `article` or `episode`. |
| `title` | Display title. |
| `link` | Canonical web/detail page link. |
| `summary` | Source-provided short summary or description. |
| `author` | Author, creator or podcast author. |
| `publishedAt` | Source publication timestamp. |
| `updatedAt` | Source update timestamp. |
| `content_md` | Markdown body used for LLM processing and infl0 display. |
| `source_type` | Source type such as `rss`, `html`, `rss+podcast`. |
| `tld` | Registered domain derived from the source URL. |
| `content_hash` | Hash over `content_md`. |

The LLM enrichment fields (`teaser`, `summary_long`, `category`, `tags`,
`seriousness_rating`) apply to both articles and episodes.

## Podcast episode fields

Podcast feeds may provide richer media metadata. The crawler forwards these
fields when present:

| Field | Description |
|-------|-------------|
| `media_url` | Direct audio/media URL from RSS enclosure. |
| `media_type` | Media MIME type, for example `audio/mpeg`. |
| `media_length_bytes` | Enclosure size in bytes. |
| `duration_seconds` | Episode duration parsed from iTunes duration. |
| `episode_number` | Podcast episode number. |
| `season_number` | Podcast season number. |
| `episode_type` | iTunes episode type such as `full`, `trailer` or `bonus`. |
| `explicit` | Source explicit flag as provided by the feed. |
| `subtitle` | iTunes subtitle or feed subtitle. |
| `image_url` | Episode image URL. |
| `categories` | Feed categories/tags. |
| `chapters_url` | Podcasting 2.0 chapters document URL when advertised. |
| `chapters_type` | Chapters MIME type. |
| `chapters` | Parsed chapter list when `chapters_url` can be fetched. |
| `chapters_fetch_error` | Error string when chapter fetching fails. |
| `transcript_url` | Transcript document URL when advertised. |
| `transcript_type` | Transcript MIME type. |

`link` remains the human-facing episode page. `media_url` is the direct media
asset and should not replace `link` in UI labels.

Parsed chapters are normalized to this shape:

```json
[
  {
    "start_seconds": 0,
    "title": "Intro",
    "url": "https://example.com/intro",
    "image_url": "https://example.com/intro.jpg"
  },
  {
    "start_seconds": 312,
    "title": "Main Topic"
  }
]
```

Podcast detail fetching builds `content_md` from feed text before trying the
episode detail page:

1. rich feed content, usually `content:encoded`,
2. otherwise description as shownotes,
3. plus `itunes:summary`/`summary` when it is present and distinct from the
   shownotes,
4. detail page fallback only when the feed has no usable text.

The LLM receives the resulting `content_md`; episodes may additionally carry
`shownotes_md` for compatibility with existing podcast rendering.

## n8n workflow note

The current workflow still passes items through fields named `article` and
`article_id`. That is a workflow compatibility detail. Consumers should inspect
`article.item_kind` / `item_kind` to decide how to render the content.
