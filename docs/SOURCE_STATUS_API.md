# infl0 Source Status API

TopicKnowledgeCrawler sends operational source status snapshots to infl0 so
infl0 can show source health in user-facing feed settings and operator views.

Endpoint:

```http
POST /api/crawler/source-status
Content-Type: application/json
Authorization: Bearer <crawler-api-key>
```

The payload is a snapshot for one source identified by `crawlKey`.
TopicKnowledgeCrawler is authoritative for observed crawler state, but infl0
remains authoritative for users, subscriptions, timeline items and article
storage.

## Required fields

| Field | Type | Description |
|-------|------|-------------|
| `crawlKey` | string | Stable source key used by infl0 and TopicKnowledgeCrawler. |
| `sourceHealthStatus` | string | One of `pending`, `needs_setup`, `healthy`, `quiet`, `degraded`, `failing`, `blocked`, `paused`. |

## Important optional fields

| Field | Type | Description |
|-------|------|-------------|
| `sourceHealthReason` | string or null | Machine-readable reason for the health status. |
| `sourceHealth` | object or null | Detailed health object generated by the crawler. |
| `operatorAttention` | boolean or null | `true` when an operator should inspect the source. |
| `operatorAttentionReason` | string or null | Machine-readable operator attention reason. |
| `lastCrawlStatus` | string or null | Last run status, usually `running`, `success`, `partial_failed` or `failed`. |
| `lastCrawlStartedAt` | ISO string or null | Last crawl start timestamp. |
| `lastCrawlFinishedAt` | ISO string or null | Last crawl finish timestamp. |
| `lastSuccessfulCrawlAt` | ISO string or null | Last fully successful crawl timestamp. |
| `lastCrawlError` | string or null | Human-readable summary of the last crawl error. |
| `nextAllowedCrawlAt` | ISO string or null | Earliest known next crawl time. This is the main field for "when can I expect data?". |
| `lastDispatchReason` | string or null | Why the dispatcher last started or skipped this source. |
| `crawlTotalCount` | number or null | Total terminal candidates in the last run. |
| `crawlCandidateCount` | number or null | Listed candidates in the last run. |
| `crawlSkippedCount` | number or null | Candidates intentionally skipped before fetch/LLM. |
| `crawlProcessedCount` | number or null | Items successfully processed and sent to infl0. |
| `crawlFetchErrorCount` | number or null | Detail fetch failures. |
| `crawlUnchangedCount` | number or null | Known items whose content did not change. |
| `crawlLlmFailedCount` | number or null | LLM processing failures. |
| `consecutiveErrorCount` | number or null | Consecutive failed or partially failed crawl runs. |
| `effectivePolicy` | object or null | Effective crawler policy after defaults, source policy and detected hints. |
| `detectedPolicy` | object or null | HTTP/RSS hints like status, cache headers, RSS TTL or Retry-After. |
| `detectedPolicyCheckedAt` | ISO string or null | When `detectedPolicy` was collected. |
| `detectedPolicyError` | string or null | Error while collecting source policy hints. |

## Health statuses

| Status | Meaning | Typical UI |
|--------|---------|------------|
| `pending` | Source is known but no crawl result is available yet. | "Wartet auf ersten Crawl" |
| `needs_setup` | Source requires analysis or configuration before it can be crawled. | "Einrichtung noetig" |
| `healthy` | Recent crawl completed without crawler-relevant problems. | "Aktuell" |
| `quiet` | Crawl works, but yielded no new usable items. | "Keine neuen Inhalte" |
| `degraded` | Crawl partially works, but some items or checks failed. | "Teilweise gestoert" |
| `failing` | Crawl currently fails or analysis failed. | "Fehler" |
| `blocked` | Source is blocked or rate-limited by the upstream service. | "Blockiert" |
| `paused` | Source is intentionally inactive or waiting for Retry-After/backoff. | "Pausiert" |

## JSON Schema

The machine-readable contract lives at
[`docs/schemas/source-status.schema.json`](schemas/source-status.schema.json).

infl0 can use the schema to validate test fixtures and incoming requests. The
schema is intentionally strict about top-level field names (`additionalProperties:
false`) so accidental n8n/Data-Table fields do not silently become public API.
