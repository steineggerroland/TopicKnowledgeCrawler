# Source Sync and Analysis Workflow

This document describes the n8n workflow that synchronizes sources from infl0 into the `Infl0-crawl-sources` Data Table and prepares them for crawling.

## Current Purpose

The workflow should:

1. call `GET /api/crawler/sources`,
2. split the returned `sources` array,
3. normalize source fields,
4. analyze source type,
5. generate HTML selector configuration when needed,
6. validate configuration,
7. upsert one row per `crawl_key`.

## Recommended Shape

1. Trigger: manual, schedule or webhook.
2. HTTP Request: `GET {{$env.INFL0_BASE_URL}}/api/crawler/sources`.
3. Split out `body.sources`.
4. Code node: unwrap each `source` object.
5. Python Code node: `normalize_source`.
6. Python Code node: `analyze_source`.
7. IF `type == "html"` and configuration is missing.
8. Python Code node: `prepare_html_analysis`.
9. n8n AI node: generate selector JSON.
10. Python Code node: `apply_html_analysis`.
11. Python Code node: `validate_source_configuration`.
12. Data Table upsert by `crawl_key`.

Do not deactivate existing rows before a successful source sync has completed. A failed HTTP call should not accidentally mark all sources inactive.

## Field Mapping

| infl0 field | Data Table field |
|-------------|------------------|
| `crawlKey` | `crawl_key` |
| `feedUrl` | `url` |
| `displayTitle` | `name` |
| `subscriberCount` | `subscriber_count` |

If `displayTitle` is missing, use `feedUrl` or `crawlKey` as fallback display name.

## `normalize_source`

```python
from tkcrawler.steps.normalize_source import normalize_source_item

out = []
for item in _items:
    out.append({"json": normalize_source_item(item["json"])})
return out
```

The step accepts either flat source rows or rows with a nested `source` object from infl0.

## `analyze_source`

```python
from tkcrawler.steps.analyze_source import analyze_source_item

out = []
for item in _items:
    out.append({"json": analyze_source_item(item["json"])})
return out
```

The step performs cheap content-type detection. It should not run an LLM.

## HTML Analysis

For HTML sources without valid configuration, prepare a compact analysis input:

```python
from tkcrawler.steps.prepare_html_analysis import prepare_html_analysis_item

out = []
for item in _items:
    out.append({"json": prepare_html_analysis_item(item["json"])})
return out
```

The n8n AI node should return JSON such as:

```json
{
  "article_selector": "article",
  "main_page_anchor_selector": "a:has(h2)",
  "confidence": "high",
  "notes": "Article cards contain links with h2 titles."
}
```

Merge the original source row and the AI output before applying analysis:

```python
from tkcrawler.steps.apply_html_analysis import apply_html_analysis_item

out = []
for item in _items:
    out.append({"json": apply_html_analysis_item(item["json"])})
return out
```

Then validate:

```python
from tkcrawler.steps.validate_source_configuration import validate_source_configuration_item

out = []
for item in _items:
    out.append({"json": validate_source_configuration_item(item["json"])})
return out
```

## Status Semantics

- `source_status = ready`: source can be crawled.
- `source_status = needs_analysis`: source needs type or HTML analysis.
- `source_status = analysis_failed`: analysis failed.
- `source_status = configuration_invalid`: HTML configuration failed validation.
- `configuration_status = generated`: generated by AI and ready for validation.
- `configuration_status = valid`: validated successfully.
- `configuration_status = invalid`: validation failed.

## Operational Notes

- Store `analysis_checked_at` on each analysis attempt.
- Store `analysis_error` or `configuration_error` instead of hiding failures.
- Keep the original URL and crawl key stable.
- Do not overwrite manually corrected HTML configuration unless explicitly requested.
- Prefer upsert by `crawl_key`.
